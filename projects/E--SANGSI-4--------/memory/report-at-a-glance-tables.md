상부 보고용 보고서(팀장→처장 이상)는 **한 눈에 들어와야** 한다. 2026-10-14 무용학과 대응(안)을
개조식 2쪽(경과표·조문 상세 포함)으로 평가자 100점까지 만들었으나 사용자가 "한 눈에 안 들어온다,
너무 세세하다"며 반려했다.

- 구조: **Ⅰ. 배경**(2~3줄) → **Ⅱ. 쟁점 검토 = 비교표**(구분 / 상대 요구 / 본부안 / 검토 의견)
  → **Ⅲ. 대응 방안 = 흐름표**(① ▶ ② ▶ ③ ▶ ④, 각 칸에 시기·핵심 2~3줄). 표 아래 ※로 결정 요청·법률자문.
- 세부 경과(날짜별 표), 조문 원문 설명은 빼고 핵심 조문 번호만 표 셀에.
- skku_report `table()`은 `{'t':'▶','rs':3}` 로 화살표 열을 행 병합해 흐름표를 만든다.
  셀 폭 12pt 1줄 수용량을 넘기면 한글이 다시 접어 글자가 흩어지니 셀 문구는 수동 `\n` 으로 짧게.

- **보고받는 사람은 아무것도 모른다고 가정**(2026-10-15 무용학과 대응안 2차 반려). 현 사안만 쓰지 말고
  ① 수년간 T/O 경과(연도·분야·결과 표) → ② 작년 실패 사유 → ③ 올해 쟁점 순으로 쓸 것.
  경과표에는 **T/O 신청·배정·채용·퇴직·재직 숫자 열**을 넣을 것. 쟁점·이해가 많은 건은 1쪽 고집 말고 2쪽 허용,
  **대응 방안이 핵심** → 흐름표만 두지 말고 단계별 세부(1)·2))·예상 리스크 표·결정 요청까지.
  **맨 앞 Ⅰ. 배경 2줄은 항상 둘 것**(없으면 어색하다는 지적, 2026-10-15). 방향이 정해진 건은 대응 방안에
  1안·2안 비교표를 넣지 말고 **채택안 하나로만** 쓸 것(선택 근거는 세부 항목 한 줄로).
  비교표에는 **역할 열**(각 위원회가 무엇을 하는지)과 **작년 열**을 넣어 작년 대비 무엇이 달라졌는지 보이게.

- **처음 보는 사람이 조문을 찾아보지 않아도 이해되게**(2026-10-15 3차 반려). 조문 번호·이전 보고 약칭("8. 6. 보고 준용", "제10조⑤ 후단", "비대위가 대행(이화여대 ’24)")만 던지지 말고
  현행 → 개정 → 효과로 풀어 쓸 것. 표 앞에는 항상 도입 문장(소제목), 소제목에 지원자 수 같은 부수 정보 금지,
  쟁점은 경과(방침 → 안 마련 → 협의 → 재요구) 뒤에 이어서. 리스크 표는 "추진 시 예상 리스크 및 대응" + 구분 열(어느 조치의 리스크인지).

- **쉬운 말로**(2026-11-02 무용학과 흐름도 반려 "왜 이렇게 어렵지, 처음 듣는데"). 호선·제척·2배수·갈음 같은 규정 용어,
  ▼ 화살표 금지, 셀은 2줄 이내. **단, 구어체로 과하게 풀면 안 됨** — "하는 일/맡는 곳/누가 추천"은 상임이사 보고자료에
  안 맞는다고 다시 반려. 행정 문체는 유지: 열 "단계 / 주요 내용 / 주관 / 위원 구성(추천)", 제목 「무용학과 전임교원 채용 절차 및 위원회 구성」,
  셀 "성적순 2명 추천", "최종 1명 선정"처럼 짧은 행정어.
  단계별 세로 표(단계마다 6열)는 "안 보인다"고 반려 → **위원회 중심**으로: Ⅱ 절차는 가로 3행 표(단계/주관/인원)로 간략히,
  Ⅲ 위원회별 행 × [역할·구성·추천권·쟁점(학과 요청)] 열. 쟁점에는 변경 전→후(내부 2·외부 3 → 내부 3·외부 2)를 꼭 적는다. 파일: `00_2026_초빙검토\_scripts\_build_보충_흐름도.py`.

**Why:** 평가자 루프는 정확성·단서는 잡아주지만 "보는 사람이 한 장에 이해하는가"는 사용자 기준이 따로 있다.
**How to apply:** 보고서 요청 시 처음부터 이 구조로 시작하고, 평가자 프롬프트에 "1쪽·표 중심·세부 생략 감점 금지"를
고정 전제로 넣을 것. 관련: [[univ-doc-evaluator-loop]] [[hwpx-report-layout-checklist]]
