보고서 본문(`∘` 세목)은 **풀어 쓴 설명형 문장이 아니라 한자어 명사구로 압축**해 쓴다. 비유·추상어 대신 **구체적인 업무 대상**을 이름으로 부른다.

**Why:** 2026.9.29. 사용자가 직접 교정해 준 어투다.

| 내가 쓴 것 | 사용자가 고친 것 |
|---|---|
| 성과가 한 곳에 쌓이지 않아 **학교 자산으로 남지 않음** | **성과 미축적**으로 **교내 교원 성과 데이터 구축 어려움** |

두 가지가 동시에 바뀐다.
1. `한 곳에 쌓이지 않아` → `성과 미축적으로` — **연결어미(~아/~라/~인데)를 한자어 명사화**로 접는다.
2. `학교 자산으로 남지 않음` → `교내 교원 성과 데이터 구축 어려움` — **추상적 비유를 실제 업무 산출물 이름으로** 바꾼다. 「학교 자산」은 결재선이 무엇을 못 만든다는 건지 알 수 없다.

## How to apply

1. **연결어미를 지우고 명사형으로 접는다.**
   - `~라 탈락 時 대안이 없음` → `~로 탈락 時 대안 부재`
   - `~해 운영 부담을 줄임` → `~ 제외로 운영 부담 경감`
   - `~인데 지원은 5年에 그침` → `~ 最長, 지원은 5年에 그침`(쉼표로 병치)
2. **비유·평가어를 업무 명칭으로 바꾼다.** 「자산」·「문을 개방」·「~하는 효과」는 쓰지 않는다.
   - `기준 충족者 全員에게 문을 개방` → `기준 충족者 全員 대상 운영`
   - `명확히 전달하는 효과` → `명확한 전달`
3. **없다는 말은 「부재」·「불가」·「어려움」·「제한」으로 끝낸다.** `~이 없음`·`~하지 않음`보다 짧고 문서투에 맞는다.
4. **사용자가 직접 쓴 줄은 건드리지 않는다.** 한글 편집본과 diff를 떠서 누가 쓴 줄인지 먼저 가린다.
   2026.9.29. 사용자 원문 — **「내가 작성한건 의도가 있는거니까 냅둬」**. 어색해 보여도 고치지 말고, 근거가 의심되면 **묻기만** 한다.
   삭제한 註도 마찬가지다(엠바고 註 삭제는 의도적이었다).
5. **다만 사용자 수정이 다른 곳과 어긋나면 그건 알린다.** 사용자가 표를 고치고 아래 서술을 안 고친 경우가 실제로 있었다
   (Ⅱ-3 표 공백 `—` ↔ 서술 「4年 공백」). 사용자 문장을 지키는 것과 문서 정합성을 지키는 것은 다른 일이다.

v5에서 이 규칙으로 18줄을 일괄 교체했다(`_scripts/build_v5.py`). 폭은 전부 14pt 한 줄(33.04em) 안에 들어갔다.
