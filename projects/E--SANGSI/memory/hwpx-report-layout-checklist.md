SKKU 회의자료(hwpxskill `skku` 템플릿)로 보고서를 쓸 때 매번 틀렸던 것들.

**1. 양식 기호는 자동으로 안 붙는다**
`r.note()`는 `※`를, `r.dash()`는 `-`를 붙여주지 않는다. 텍스트에 직접 넣어야 한다.
빼먹으면 양식 위반인데 추출문에서도 눈에 잘 안 띈다. 래퍼 함수에서 자동 부착 권장.

**2. 표가 쪽을 넘기면 잘린다**
표 높이 = Σ(행별 최대 줄수 × 1920 + 282) HWPUNIT. 쪽 본문 높이는 **262mm**(297−20−15).
비교표처럼 한눈에 봐야 하는 표가 이걸 넘으면 두 쪽으로 갈라진다.
→ 표에는 흐름·주관 기구만 넣고 세부 조건은 본문/붙임으로 뺀다. 목표 200mm 이하.

**3. 분량 배분 (회의자료 기준)**
표 1개 = 0.6~0.8쪽. 본문 3쪽에 표 2개를 넣는 건 물리적으로 불가능하다.
현실적 하한은 **본문 5쪽**이며, 상세 운영기준·공정성 장치는 `<붙임1>`, `<붙임2>`로
분리한다(경영진보고 "본문 + 별첨" 구조와 동일).
분량 추정은 verify_layout.py가 장별 시작 쪽까지 출력해준다.

**4. bash heredoc으로 파이썬 패치 스크립트를 쓰지 말 것**
`<<'PYEOF'` 안에서 `\n`이 실제 개행으로 들어가 대상 파일이 깨진다.
패치 스크립트는 Write 도구로 `.py` 파일을 만들어 실행한다.

**Why:** 사용자가 "양식에 안맞고 난리도 아니야"라고 한 원인이 1·2번이었고,
3번 때문에 회의자료가 15쪽까지 부풀었다. 4번으로 빌더 파일을 한 번 깨뜨렸다.

**How to apply:** 빌드 → `verify_layout.py` → 텍스트 추출로 육안 확인 순으로 검증하고,
"[줄 폭 경고 없음]"만 보고 완료 처리하지 않는다.
