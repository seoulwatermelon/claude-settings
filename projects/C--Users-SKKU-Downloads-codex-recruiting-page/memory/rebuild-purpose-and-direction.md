2026-11-10 사용자가 직접 말한 문제인식(정시·상시를 한 바퀴 돌고 도메인 지식을 쌓은 뒤 재개):
- 버리고 있는 데이터가 많다.
- 학과장 → 실무자 → 경영진 보고가 같은 내용을 전달-전달하는 식이다(사용자 표현 '파랑새').
- 학과장도 같은 형식의 답을 메일로 반복하고, 채용이 어디까지 왔는지 몰라 불편하다.
- 통합정보시스템(ASIS)은 API가 안 되고 AI 기반으로 갈 수 없다.
- 최종 목적지: 전 학과 교원의 분야별 정리. 과거 데이터로 잠재력 있는 신규 교원 선발(사용자는 MiroFish를 언급).

방향: 학과장 입력 + 총장·상임이사까지 권한별 열람(이전 논의의 C안). 사용자가 "사이트를 갈아엎어라, 에이전트를 써서 진행, 평가자 100점이면 멈추고 보고"라고 지시.

기준 문서: `docs/superpowers/specs/2026-11-10-rebuild-design.md` (가치 4개, 역할 EXEC/HR/DEAN/CHAIR, 사실 저장소 facts로 재입력 제거, 추가 전용 stage_events).

**Why:** 3월 버전은 업무를 해보기 전에 상상한 절차라 실제와 어긋났고, 이 프로젝트 키에는 세션·메모리가 남아 있지 않아 '왜 하는가'가 유실됐었다.
**How to apply:** 기능을 넣고 뺄 때 위 문제에 답하는지로 판단한다. MiroFish는 조사 결과 예측 점수 용도로 부적합(LLM 역할극 요약, 검증 불가, 채용은 인공지능 기본법 고영향 영역)하다고 사용자에게 보고했고 — 사용자의 최종 판단은 아직 받지 못함. 관련 조사 근거: 실제 절차는 JUNGSI·E:\SANGSI 폴더와 그 메모리에 있다.
