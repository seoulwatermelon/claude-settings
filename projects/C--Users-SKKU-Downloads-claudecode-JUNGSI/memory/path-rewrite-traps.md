2026-10-26 JUNGSI 정리에서 경로를 일괄 수정하며 일곱 번 틀렸다. 전부 내 쪽 실수다.

1. **슬래시도 절대경로다. 그리고 이 실수는 거울상으로 다시 온다.**
   처음엔 역슬래시 형태만 세고 "절대경로 0건"이라 보고해 `'C:/Users/.../JUNGSI/...'`
   55건을 빠뜨렸다. 나중에 고칠 때는 **슬래시 형태만 치환해서**
   `r'C:\Users\SKKU\.claude\skills\hwpxskill'` 을 놓쳤다. 한 방향만 보면 반대쪽이 남는다.
   비교 전에 `v.replace('/', os.sep)` 로 통일할 것.
   **일반형: 세는 패턴과 고치는 패턴이 같은지 확인하라.** 다른 축에서도 작동한다.
   세 번 어겼다 — 역슬래시로 세고 슬래시만 고침 / JUNGSI 안만 세고 "0건" 보고 /
   형식 검사를 대입 자리로 세는데 정작 볼 것은 opener 까지의 흐름이었다.
   **세는 범위도 함께 밝힐 것.** 내 검사는 JUNGSI 안을 가리키는 것만 셌는데 그걸
   말하지 않고 "0건"이라 했다. 밖을 가리키는 절대경로(`~\.claude\skills`, `%TEMP%`)가
   오히려 다른 PC·다른 담당자에게 더 빨리 깨진다. 드라이브 문자로 시작하면 안이든
   밖이든 센 다음 안팎을 나눠 보고하라.
2. **`ast` 의 `col_offset`·`end_col_offset` 은 UTF-8 바이트 오프셋이다.** 한글이 든 줄에서
   그 값으로 `str` 을 슬라이싱하면 엉뚱한 자리가 잘린다. 줄을 `encode('utf-8')` 해서
   바이트로 자르고 다시 `decode` 하거나 `ast.get_source_segment` 를 쓸 것.
3. **같은 성격의 일괄 변환을 두 번 돌리지 말 것.** 두 번 돌려
   `os.path.join(BASE, os.path.join(_ROOT, …))` 중첩이 106군데 생겼다.
   (`os.path.join` 은 뒤 인자가 절대경로면 앞을 버리므로 뜻은 같지만 읽을 수 없다.)
4. **경로처럼 생긴 문자열이 전부 경로는 아니다.**
   `==`·`in`·dict 키 자리의 값은 **이름**이다. 바꾸기 전에 그 값이 비교되는지 보라.
   `F.replace('.xlsx', '_백업.xlsx')` 의 접미사, `z.namelist()` 와 맞춰 보는
   `endswith('section0.xml')`, `if fname == '교원조회_260518.xlsx'`,
   그리고 `STAT_PDF = '…(통계학과).pdf'` 를 `listdir('.')` 결과와 비교하던 자리.
   **이 부류를 다섯 번 틀렸다.** 독스트링·주석·f-string 안쪽·정규식 안쪽도 건드리면 안 된다.

   마지막 것(`STAT_PDF`)은 **아홉 축을 전부 통과했다.** 바뀐 값이 실존하는 유효한
   경로였고, 원본이 절대경로가 **아니었으니** 값 검증의 비교 대상도 아니었다.
   그래서 축을 하나 더 둔다 — **"절대경로로 해석되는 값이 `==`·`in` 으로
   맨 파일명 출처(`listdir`·`glob`·`basename`)에서 온 변수와 비교되는 곳"**.

5. **원시문자열의 접두어 `r` 을 같이 지워야 한다.** `r'C:/...'` 의 따옴표 안쪽만 바꾸면
   `ros.path.join(...)` 이 남는다. **구문 검사와 경로 검사를 둘 다 통과하고 돌리면 NameError 다.**
   7곳에 그렇게 만들었고 평가자가 발견했다.
6. **스크립트를 옮기면 `BASE = dirname(abspath(__file__))` 의 뜻이 바뀐다.** 자기 폴더를
   자료 폴더로 쓰던 스크립트는 입력을 못 찾고 출력이 `_scripts` 에 떨어진다. 10곳을 깨뜨렸고,
   그중 `_build_정리.py` 는 `_update_*.py` 가 읽는 자리와 어긋나 파이프라인이 끊겼다.
   옮기기 전에 `__file__` 기준 변수를 먼저 찾을 것.
7. **경로 변환과 앵커 배치를 분리하면 안 된다.** 세 번 분리했고 세 번 다 `_ROOT` 가
   정의 없이 쓰여 NameError 가 났다. 같은 단계에서 앵커 유무를 함께 확인할 것.

**Why:** 일곱 번 모두 "바꾼 개수"로 검증해서 통과했다. 개수는 맞는데 뜻이 틀렸다.
[[verification-two-axes]] [[verification-circular-trap]] 과 같은 뿌리다.

**How to apply:** 고친 뒤 네 축으로 확인한다. 개수 비교는 쓸 수 없다.
① **값** — 바꾼 식을 평가해 원래 경로와 글자까지 같은지, 다르면 되돌린다.
② **이름** — 정의되지 않은 이름을 쓰는 곳이 없는지(`ast` 로 `Load` 되는 `Name` 에서
   묶인 이름을 뺀다. `from x import *` 있는 파일은 보류). 구문 검사로는 안 잡힌다.
③ **앵커 실행** — 앵커 블록만 떼어 `exec` 해 `_ROOT` 가 정말 루트가 되는지.
④ **기능** — `01_교원확보율/_scripts/verify.py` 27,371건. 유일한 실제 실행 시험이다.

**대조는 대상이 존재할 때만 작동한다. 형식 검사와 짝으로 둬라.**
대상이 아예 없으면 형식 위반도 함께 묻힌다 — `FN = '…ver15.xlsx'` 가 그 증거다.
앵커 없는 맨 파일명이었는데 ver15 가 트리에 없어서 ORPHAN 으로 분류되고
양쪽 스캐너 보고에서 빠졌다. 그래서 축을 하나 더 둔다 —
**"앵커 없는 맨 파일명·상대경로는 대상 존재 여부와 무관하게 전부 보고"**.
표(dict/list) 안의 값과 `join` 인자 안쪽은 면제하되, 조용히 빼지 말고 따로 센다.

판정 기준은 **열거가 아니라 대조**로 세운다. "아는 함수(`open`·`load_workbook`)의 인자"로
찾으면 `apply('_data/x.json')` 같은 사용자 정의 함수를 영원히 못 본다. "그 문자열의
basename 이 트리에 실제로 있는가"로 바꾸면 미지의 호출 형태에도 작동하고, 로그 문장과
ZIP 내부 이름(`Contents/section0.xml`)이 자동으로 걸러진다.
