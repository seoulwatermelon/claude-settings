교인협 HWPX 빌더(`_build_field.py`)의 서식 규칙. charPr ID는 **파일마다 다를 수 있으니 시각속성(height/bold/underline)으로 판단**해야 한다([[hwpx-text-extraction-pitfall]] 참고). 아래는 샘플 템플릿(팀장님 원본) 기준 정답:

- **평가결과표(표2) 학사·최종학위·현직**: 볼드 금지. 일반 본문(height 900, bold X). 샘플 charPr=45. (구버전은 46=볼드로 강제하던 버그)
- **외부 심사위원 채용 의견 표(표10)**: 글자크기 900 통일. **최상위 평가항목만 볼드+밑줄**(샘플 82), 상위(높음/국내상위/적극채용)=볼드(59), 그외(보통/낮음/채용보류/미채용)=일반(45). 구버전 83/60/46은 밑줄누락·60은 height 1100 확대 버그.
- **2단계 심사표(표9, ▮2단계 심사 평가결과)**: 점수=일반(45). 채용라벨은 표10과 동일 스킴 — 최상위 `[매우적극채용]`=볼드+밑줄(82), `[적극채용]`=볼드(59), 그외(보통/채용보류/미채용)=일반(45). (샘플 원본은 표9에 밑줄이 없었으나 팀장님이 최상위 등급에 볼드+밑줄 요청). 표9 라벨은 공백 없는 `[매우적극채용]` 형식이니 검증 시 공백 무시(normalize)할 것.
- **Global Peer Review 그래프 점(●)**: **빨강**(#FF0000, 샘플 charPr 108). 파랑(#3300FF, 109) 아님.
- **전차 공개전형 지원이력 본문**: 주요경력과 같은 본문 서식(charPr 28). 제목 서식 쓰면 안 됨. 내용 끝에 **빈 줄 1개(Enter)**. 형식: `° YYYY년 정시채용 (분야: X)` + `   - 심사결과: Y`. 분야/결과는 config `과거지원_분야`·`과거지원_결과`(키만 있으면 값 비어도 빈칸 자리 렌더).
- **GPR 분석개요 표 다토픽(≥2)**: 데이터행 높이 균등(4022). 템플릿은 첫 행만 2890이라 들쭉날쭉.

**Why:** 확정본 파일들이 시기별로 다른 charPr을 써서 일부는 이미 올바르고(미디어·건축·양자) 일부는 확대·밑줄누락 버그(물리 등)로 뒤죽박죽이었다. 새 스킴으로 18개 전부 시각 통일. 검증은 charPr ID 비교가 아니라 시각속성(height/bold/underline) 매핑으로 해야 한다.
