산출물 검증은 **두 축**이 필요하다. 하나만 세우면 반드시 뚫린다.

1. **계산 축** — 엑셀 수식이 규칙대로 동작하는가.
   규칙을 파이썬으로 **독립 구현**하고, 엑셀은 COM(`pywin32`)으로 강제 재계산해 셀 단위로 대조한다.
2. **원본 대조 축** — 시트에 들어간 데이터가 원본 서류와 맞는가.
   평가자에게 **판단 근거는 감추고 확정값만** 주어 원본 서류로 직접 대조시킨다.

**원본 대조는 방향이 둘이고, 한 방향만 보면 뚫린다.**

- (가) 산출물 → 원본: "내가 쓴 값이 원본에서 왔나" — **틀린 값**을 잡는다.
- (나) 원본 → 산출물: "원본 조각이 결과물에 남았나" — **빠진 값**을 잡는다.

(가)만 세우면 **지운 것은 영원히 안 보인다.** 2026-10-29 발령장 명단에서
48명 List 의 `*University College London` 을 떨어뜨렸는데, 11개 축 1,721항목이
전부 통과했고 평가자가 잡았다. (나) 축을 넣자 바로 걸렸다.
검사 축을 만들면 **일부러 그 결함을 주입해 축이 실제로 잡는지** 확인하라
([[verification-circular-trap]]).

**정규화는 매칭에만 쓰고 대조에는 쓰지 마라.**

- **매칭**(사람·학과를 찾을 때): 정규화한다. 원본 간 표기 흔들림을 넘어야 한다.
- **대조**(값이 같은지 볼 때): 정규화하지 않는다. 구분자·줄나눔·공백까지
  원문 그대로 비교하고, 다르면 **의도한 override 목록에 있는지로만** 통과시킨다.

정규화는 원본의 표기 흔들림을 흡수하려고 넣는데, **내가 바꾼 표기도 같이
흡수**한다. 2026-10-29 발령장 명단에서 `·`→`.` 정규화 때문에 내가 소속을
가운뎃점으로 바꿔 놓은 2건이 나와 평가자 양쪽 축에서 '차이 없음'으로 통과했다.
허용 목록을 사람 이름으로 못 박으면 '조직개편 때문에 바꾼 값'과
'실수로 바뀐 표기'가 갈린다.

**원본의 오타를 고칠 때는 등록제로 하라.** 조용히 고치면, 다음에 원본이
고쳐졌을 때 그걸 모르고 내 교정값이 계속 이긴다. 교정 대상마다 **원본 문자열을
함께 적어 두고 대조하는 단정문**을 걸어, 원본이 바뀌면 멈추게 한다. 정규화가
변경을 가리는 것과 같은 계열의 함정이다.

**전례는 반대 방향까지 찾아라.** 전례 한 건으로 규칙을 정하면 뒤집힌다.
구버전 파일의 오류 값을 전례로 쓰거나(v3 김도윤 `30.8.14.` → v7 `28.8.14.`),
여러 열이 서로 다른 규칙을 쓰는 것을 못 보게 된다(발령장 명단은 소속 열만
마침표, 분야 열은 가운뎃점).

**Why:** 계산 축은 엑셀과 파이썬을 **같은 데이터**로 비교한다. 데이터 자체가 오염되면 양쪽이 똑같이 틀려서 그대로 100점이 나온다. 2026-08-24 직급산정에서 보정 스크립트가 멱등하지 않아 한 경력구간이 5중 복제됐는데, 2,000여 개 검사가 전부 통과했고 원본 대조 감사만 잡아냈다.

**How to apply:**
- 계산 축에 **데이터 정합성 검사**를 반드시 같이 넣는다: 동일 구간 중복, 산입 구간끼리 기간 겹침, 합계행 중복 기입, 참조 대상과 요약값 일치.
- 평가자에게는 검수 사유·판단 근거를 주지 말 것. 주면 같은 실수를 그대로 따라간다.
- 데이터를 고치는 스크립트는 **멱등**해야 한다. 사람/레코드 단위로 `_적용이력` 표시를 남기고, 두 번 실행해 결과가 같은지 확인한다.
- 지적을 반영한 뒤에는 **재감사로 닫는다**. 반영 과정에서 새 오류가 생긴다.
