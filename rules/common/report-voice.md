# 행정 보고서 문체·구성 규칙

> 사용자·팀장 피드백으로 확정(2026-11-10, 교수연구실 공간 보고서). 한글 보고서·회의자료를 쓰거나 고칠 때 모든 프로젝트에 적용. 줄 넘김은 [hwpx-report-line-wrap.md](./hwpx-report-line-wrap.md).

팀장의 평: "숫자는 다 들어가 있는데 무슨 말을 하는지 친절하지 않다. 표와 수치로 파트를 끝내고 하고 싶은 말이 없다. 휴먼 터치가 필요하다. 어색한 표현이 많다. 윗분들이 일일이 계산해야 하느냐."

## 구성

- **한 절의 순서는 제목 → `-` 메시지 줄 → 표.** 표를 보기 전에 무엇을 봐야 하는지 먼저 말한다. 그림은 제목 바로 아래에 두고 설명 `-` 줄을 그 뒤에 둔다.
- **제목에 결론과 핵심 수치를 넣는다.** "1. 전체 현황 : 총 연구실 428실 중 즉시 배정 가능 공실 5실"처럼 쓰고, 결론 부분은 굵게+밑줄로 강조한다.
- **부가설명 `-` 줄은 적게.** 배경은 항목당 1줄 이하(짧으면 제목 끝 괄호로 붙인다). 다른 절도 1~3줄.
- **`→` 줄은 결론을 내고 싶은 특정 자리에만**(문서 전체에 한두 곳). 모든 표 아래에 달지 않는다.
- **`※` 주석은 꼭 필요한 것만.** 기준일·산식 설명을 줄줄이 달지 않는다.
- **본문에 계산식을 쓰지 않는다.** "임용 18명(확정 8+진행 10) − 가용 11실(…) = 7실" 같은 줄은 표가 맡고, 본문은 판단만 쓴다.
- **근거 수치는 붙임 표로.** 본문 주장에 숫자 근거가 필요하면 붙임에 표를 싣고, 붙임 번호는 본문에서 인용되는 순서로 매긴다.
- **두 항목이 같은 내용을 다르게 말하지 않게 한다.** 변하지 않는 결론(연말 7실 부족)과 조건에 따라 변하는 값(1학기 0~7실)을 항목으로 나누고, 표에는 범위로 적는다.
- **구차한 범위 설명을 하지 않는다.** 표의 합계가 독자가 아는 숫자와 다르면(호실 459 vs 전임교원 423명) 해명을 달지 말고, 독자가 아는 기준에 맞춰 표를 다시 짠다.

## 문체

- **명사형으로 끝나는 보고서체.** "~임/~함"도 줄이고 "부족", "예정", "필요", "증가"로 끝낸다.
- **구어·강조 표현 금지.** "2031년에야 가능" → "2031년 예정". "신규임용이 퇴직보다 많아 계속 증가" → "신규임용이 퇴직 인원을 상회하여 전임교원 순증". "비는 16실" → "발생하는 16실".
- **과장어 금지.** 급증·급감·등락·심화 대신 "빠르게 증가", "학기당 5~13실 발생".
- **기호 나열을 문장으로.** 본문에서 `A > B`, `X → Y`, "1명당 1실"을 줄이고 조사와 서술어를 살린다. `△`는 표 안에서만.
- **한 항목은 한 줄에.** 넘치면 문장을 줄인다(15pt 약 32자, 14pt 약 34자, 13pt 약 37자. 숫자·영문은 반 자).

## 수치

- **기간·기준이 다른 숫자를 나란히 비교하지 않는다.** 과거 실적 평균(임용 13명)과 미래 전망(퇴직 9.5명)을 한 줄에 놓으면 독자가 근거를 따라갈 수 없다.
- **출처 없는 숫자를 만들지 않는다.** 보간·역산한 값은 표에 그렇게 표시하고, 완료 보고에서도 밝힌다.
- **기준 수치가 하나 바뀌면 문서 전체를 따라 고친다.** 제목, `-` 줄, 표, 그림, 결론, 붙임을 모두 고친 뒤 옛 숫자가 남았는지 본문 전체를 검색한다.
- **사용자가 넣은 숫자가 문서 안 다른 숫자와 안 맞으면** 임의로 바꾸지 말고 계산 근거와 함께 알린 뒤 지시를 받는다.

## 작업 방식

- **수정 지시는 동사 그대로.** "다시 작성"은 그 절을 새로 쓰고, "보여주기"는 표·그림으로, "써주기"는 지정한 문구로. 덧붙이기나 주석 한 줄로 줄이지 않는다.
- **사용자가 한글에서 고친 파일이 최신이다.** 수정 전에 그 파일을 다시 풀어 그 위에서 작업한다. 사용자가 바꾼 문장·순서·서식은 지시가 없으면 건드리지 않는다.
- **버전을 임의로 올리지 않는다.** 현재 작업본에 덮어쓰고, 새 파일은 사용자가 "버전 새로 파라"고 할 때만.
- **완료 보고 전에 한글로 PDF를 뽑아 직접 본다.** 줄 넘김, 글자 눌림, 표 꺾임, 쪽 배치를 확인한다.

## 문장 완결성 (2026-11-17 확정, 교원채용 AI 공모 신청서 — 이 규칙 적용 후 품질이 크게 올랐다는 사용자 평)

- **모든 줄에 누가(주어)·무엇을(목적어)·어떻게(서술어)를 쓴다.** 명사만 늘어놓지 않는다.
  - "학과 1회 입력, 경영진 보고 자동 생성" → "학과가 1회 입력한 데이터로 경영진 보고자료 자동 생성"
  - "AI 초안" → "AI가 초안 작성", "온톨로지 기반 분야지도·잠재력 예측" → "온톨로지 기반 데이터 구축으로 학과별 분야지도 완성, 후보자 잠재력 예측"
- **주체를 구분한다.** 사람(담당자·학과·위원회), 시스템(플랫폼), AI가 각각 무엇을 하는지 섞지 않는다. 처리 순서가 중요하면(가명처리 → AI 추출) 순서대로 쓴다.
- **표 제목·그림 안 문구도 같은 기준.** 구어체 표 제목 금지, 그림의 짧은 문구도 주어·서술어를 살린다.
- **사전에 없는 조어 금지.** '이력성', '자산성'처럼 명사에 '-성'을 붙여 만든 말을 쓰지 않는다. 머리어를 '-성'으로 맞추려다 생기므로, 맞지 않으면 '(시점별 이력)', '(자산화)'처럼 풀어 쓴다.
- **두 줄이 서로 부딪히지 않게 한다.** 예: "AI 산출물은 결정 근거가 아님"과 결론 "AI는 근거 제시"가 충돌 → "결정을 대신하지 않음".
- **양식이 정한 항목명은 머리어로 그대로 쓴다**(심사위원이 대조). 어색해도 양식 용어면 유지.

## 수치·출처 (2026-11-17 확정)

- **모든 수치의 출처 파일·기간을 즉답할 수 있어야 한다.** 쓸 때 메모리에 '수치 → 원자료 파일·기간'을 함께 기록한다.
- **표 제목의 기간과 칸마다의 기간을 맞춘다.** 기간이 다른 자료가 섞이면 수치를 빼고 '보유 기간' 열을 둔다.
- **그 자리에 꼭 필요하지 않은 구체 수치는 넣지 않는다**(배경·품질 요소 설명 등). 수치는 근거가 필요한 곳 한두 군데에만.
- **이름이 내용과 맞는지 확인한다.** DB 행 수를 셀 때 항목 구성을 확인(예: '채용·퇴직 761건'이 실제로는 교원 수·전망치 포함).
- **원자료가 갱신되면 문서 수치도 맞춘다**(38명 → 43명 등). 바꾸기 전 사용자에게 알린다.
- **출처 없는 ※ 주석을 만들지 않는다.** 주석의 정의 문구도 문서나 사용자 확인에 근거해야 한다.

## 검토 방식 (2026-11-17 확정)

- 초안을 쓴 뒤 독립 평가자 에이전트에 문체 규칙과 사실 목록을 주고 채점받아 100점까지 고친다(문장 완결성·주체 구분·수치 출처를 채점 항목에 넣는다).
- 사용자가 한글에서 손본 뒤에는 원고(md)로 재빌드하지 않고 HWPX를 직접 고친다. 그림은 같은 픽셀 크기 PNG로 BinData만 교체.
